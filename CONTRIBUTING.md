# Contribución

1. No modificar `main` directamente salvo la inicialización técnica inevitable del repositorio vacío.
2. Crear una rama por cambio y abrir un pull request.
3. Documentar alcance, evidencia, riesgos y comandos ejecutados.
4. Ejecutar `npm install --no-audit --no-fund` y `npm run build` antes de solicitar revisión.
5. No introducir claims de producción sin evidencia verificable.
6. No añadir credenciales, datos personales ni secretos.
7. Las acciones destructivas deberán requerir confirmación y dejar un evento de auditoría cuando exista backend.
